# Playbook

The single source of truth for **how Lumiera films look, move, read and sound**, and for **how the
Lumiera brand looks and talks**. Every agent, model and person working in this repo follows it.

| File | Covers |
|---|---|
| [`film-style.md`](film-style.md) | Format and safe zones, film structure and pacing, visual language, the device toolkit (counter, STEP chip, measuring row, YOU pin, meter), typography, numbers and claims, sound, definition of done |
| [`brand.md`](brand.md) | Identity, logo, colour, type, voice, posting rules, content pillars |
| [`ideas.md`](ideas.md) | Idea backlog by pillar, and what has been made |

## How to use it

1. Read `film-style.md` and `brand.md` **before** creative work on a film, a post, a cover or copy.
2. Start from the reference implementations instead of from scratch:
   - Films: `doubling_film/` (scene, devices, textures, soundtrack, render pipeline).
   - Brand assets: `lumiera_brand/` (logo and all images are generated by `build_brand.py`).
3. Before calling a film done, go through the **Definition of done** in `film-style.md` §8.

## Changing the playbook

The playbook describes what we actually ship. If a film or asset needs to break a rule, either:
- keep the rule and fix the work, or
- change the rule **here** in the same pull request, saying why in the commit message.

Never let the work and the playbook silently disagree. The tool-specific files (`AGENTS.md`,
`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`) only point here. Don't put rules in
them that aren't in the playbook.
